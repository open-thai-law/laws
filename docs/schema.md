# รูปแบบข้อมูล (schema)

เอกสารนี้อธิบายรูปแบบของไฟล์และ commit ใน repo นี้ ถ้าจะเขียนโปรแกรมอ่านข้อมูล ยึดตามนี้ได้ รูปแบบจะเปลี่ยนเฉพาะใน release ใหม่ และจะเขียนไว้ใน release notes ทุกครั้ง `scripts/validate.py` ตรวจทุกข้อในหน้านี้ที่ตรวจด้วยเครื่องได้

## ไฟล์ `acts/*.md`

หนึ่งไฟล์ต่อกฎหมายหนึ่งฉบับ เป็น UTF-8 (Unicode NFC) ขึ้นบรรทัดด้วย LF ไม่มี BOM

### ชื่อไฟล์

มาจากชื่อในสารบัญของกฤษฎีกา โดย:

- ตัด "และที่แก้ไขเพิ่มเติม" และ "(ยกเลิก)" ออก
- "พระราชบัญญัติ" → "พ.ร.บ." และ "พุทธศักราช" / "พระพุทธศักราช" → "พ.ศ."
- "/" → "-" และเลขอารบิกเป็นเลขไทย
- ชื่อที่ยาวเกิน 240 ไบต์จะถูกตัดแล้วต่อท้ายด้วย `… <law_code>` ชื่อที่ซ้ำกับฉบับอื่นจะต่อท้ายด้วย ` <law_code>`

ชื่อไฟล์ใช้เปิดอ่านได้สะดวก แต่ไม่ใช่ตัวระบุถาวร ถ้าจะอ้างอิงกฎหมายในโปรแกรม ให้ใช้ `law_code`

### frontmatter

บล็อกแรกของไฟล์ อยู่ระหว่างบรรทัด `---` สองบรรทัด บรรทัดละหนึ่งค่า ในรูป `key: value` ค่าที่ขึ้นต้นด้วย `"` เป็นสตริง JSON ส่วนค่าอื่นเป็นข้อความตรงตัว

| key | ชนิด | ความหมาย |
|---|---|---|
| `title` | string | ชื่อกฎหมายตามส่วนชื่อของเอกสาร ถ้าเอกสารไม่มีส่วนชื่อ ใช้ชื่อในสารบัญแทน |
| `published` | `YYYY-MM-DD` | วันประกาศในราชกิจจานุเบกษา (ปฏิทินเกรกอเรียน) |
| `source` | string | แหล่งข้อมูล ตอนนี้มีค่าเดียวคือ `searchlaw.ocs.go.th` |
| `law_code` | string | รหัสกฎหมายของกฤษฎีกา ไม่ซ้ำกันทั้ง repo ใช้เป็นตัวระบุถาวร |
| `status` | `in-force` \| `repealed` | สถานะ ณ วันที่ดึงข้อมูล |
| `url` | URL | หน้าของกฎหมายฉบับนี้ในระบบค้นหากฎหมายของกฤษฎีกา |
| `unofficial` | `true` | ย้ำว่าไม่ใช่ฉบับทางการ |

### เนื้อหา

```markdown
# <ชื่อกฎหมาย>

<คำปรารภ ย่อหน้าละหนึ่งบรรทัด>

## <หมวด / ส่วน / ลักษณะ / บรรพ / บทเฉพาะกาล>

### มาตรา <เลขไทย เช่น ๑๒/๑ หรือ ๓ ทวิ>

<วรรค หนึ่งบรรทัดต่อหนึ่งวรรค อนุมาตรา (๑) (๒) ก็บรรทัดละหนึ่งข้อ>

---

<ผู้รับสนองพระบรมราชโองการ>

> <หมายเหตุท้ายกฎหมาย>
```

- ย่อหน้าคั่นกันด้วยบรรทัดว่างหนึ่งบรรทัด
- `##` คือหัวข้อโครงสร้าง ส่วน `###` ใช้กับมาตราเท่านั้น จึงหามาตราได้ด้วย regex `^### มาตรา (.+)$`
- กฎหมายที่ต้นทางไม่มีตัวบท (ราว 190 ฉบับ) มีแค่หัวข้อและข้อความ "โปรดดูรายละเอียดที่ราชกิจจานุเบกษา"

## `index.csv`

CSV ตาม RFC 4180 เข้ารหัส UTF-8 มีแถวหัวตาราง หนึ่งแถวต่อหนึ่งไฟล์ใน `acts/` เรียงตามชื่อไฟล์ คอลัมน์อธิบายไว้ใน [`datapackage.json`](../datapackage.json) ตามมาตรฐาน [Frictionless Table Schema](https://specs.frictionlessdata.io/table-schema/)

| คอลัมน์ | ความหมาย |
|---|---|
| `file` | path ของไฟล์ เช่น `acts/พ.ร.บ.….md` |
| `title`, `law_code`, `status`, `published`, `url` | ค่าเดียวกับ frontmatter ของไฟล์นั้น |
| `versions` | จำนวน commit ที่แก้ไฟล์นี้ (ฉบับแรก + จำนวนครั้งที่แก้) |

## commit

หนึ่ง commit คือกฎหมายหนึ่งฉบับเปลี่ยนจากสถานะหนึ่งไปอีกสถานะ (ตราขึ้นใหม่หรือถูกแก้ไข) ตามลำดับเวลา

| ส่วน | ค่า |
|---|---|
| author name | ผู้ตรากฎหมายฉบับที่ทำให้เกิดการเปลี่ยนแปลง เช่น `รัฐสภา`, `สภานิติบัญญัติแห่งชาติ`, `คณะปฏิวัติ` ถ้าระบุไม่ได้ใช้ `ไม่ระบุ` |
| author email | `legislature@open-thai-law.invalid` เสมอ (โดเมน `.invalid` ไม่มีอยู่จริงโดยตั้งใจ) |
| author date | วันที่มีผลบังคับใช้ เวลา 09:00 +07:00 ถ้าก่อนปี 1970 ลงเป็น 1970-01-02 เพราะ git เก็บวันที่ก่อนนั้นไม่ได้ |
| committer | `open-thai-law <bot@open-thai-law.invalid>` |
| บรรทัดแรก | ชื่อกฎหมายเมื่อตราขึ้นใหม่ หรือ `แก้ไขโดย <ชื่อกฎหมายฉบับที่แก้>` |
| `มีผลบังคับใช้ YYYY-MM-DD` | วันที่มีผลบังคับใช้จริง (ใช้บรรทัดนี้แทน author date ถ้าเป็นกฎหมายก่อนปี 1970) |
| `ผู้ตรา: X (อนุมาน…)` | มีเฉพาะเมื่อผู้ตราอนุมานจากสภาที่ตรากฎหมายฉบับใกล้เคียง ไม่ได้มาจากคำปรารภ |
| บรรทัดที่เหลือ | เชิงอรรถของกฤษฎีกา เช่น `มาตรา ๑๔ แก้ไขเพิ่มเติมโดย…` |

commit ที่แก้เอกสาร (README, scripts ฯลฯ) หรือแก้ข้อมูลตามที่มีคนแจ้งใน Issue ใช้ผู้เขียนเป็นบัญชี GitHub ของผู้ดูแล จึงกรองเฉพาะประวัติกฎหมายได้ด้วย `git log --author=@open-thai-law.invalid`

ลำดับการหาผู้ตรา:

1. สภาที่ระบุในคำปรารภ ("…โดยคำแนะนำและยินยอมของรัฐสภา")
2. ผู้ออกที่ระบุในชื่อ (ประกาศ / คำสั่งของคณะปฏิวัติ, คสช. ฯลฯ)
3. พระมหากษัตริย์ สำหรับกฎหมายก่อน 24 มิ.ย. 2475
4. คณะรัฐมนตรี สำหรับพระราชกฤษฎีกาและพระราชกำหนด
5. สภาที่ตรากฎหมายฉบับใกล้ที่สุดทั้งก่อนและหลัง เมื่อทั้งสองฉบับตรงกัน (เขียนบอกไว้ใน commit)
6. `ไม่ระบุ`

## tag และ release

ชื่อ tag เป็นวันที่ดึงข้อมูล (`YYYY-MM-DD`) ถ้าออก release ซ้ำโดยใช้ข้อมูลชุดเดิม (เช่น แก้เอกสาร) ต่อท้ายด้วย `.1`, `.2` แต่ละ release เป็น snapshot ของข้อมูลทั้งหมด ณ วันนั้น release notes บอกว่ามีกฎหมายอะไรเพิ่ม แก้ หรือยกเลิกจากรอบก่อน
